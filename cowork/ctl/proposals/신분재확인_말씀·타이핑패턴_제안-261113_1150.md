# 자리 비운 사이의 대리 지시를 잡아내는 신분 재확인 체계 — 제안

- 올린 모델: Fable 5.2 · 2026-11-13 · 근거: 이력 1131(11:21)·1132(11:23)
- 성격: 대표님께 올리는 제안입니다. 정하시는 대로 정책 지시(91_02_03)로 바꿔 시행합니다.

## 1. 지금 비어 있는 곳

신분 확인은 창을 열 때 ic.hiven.ai.kr/id.html 에서 한 번 하고, 그 뒤로는 다시 하지 않습니다. 그래서 노트북이 열린 채 자리를 비우시면, 그 사이에 앉은 사람이 치는 글도 대표님 지시와 똑같이 받아들여집니다.

## 2. 모델이 실제로 받는 것 (구상의 바탕)

| 대표님이 말씀하신 패턴 | 모델에게 오는가 | 쓸 수 있는가 |
|---|---|---|
| 목소리(음색·억양·빠르기) | 오지 않음. 음성은 글자로 바뀐 뒤에 도착 | 쓸 수 없음 |
| 타이핑 박자(누르는 간격·속도) | 오지 않음. 완성된 글만 도착 | 쓸 수 없음 |
| 말버릇·낱말·문장 길이·되묻는 방식(「알겠어?」「뭐냐?」) | 글에 그대로 남음 | 쓸 수 있음 |
| 점·쉼표·띄어쓰기 버릇, 음성 인식 특유의 오자(「결제」「오파스」) | 글에 그대로 남음 | 쓸 수 있음 |
| 흥분했을 때의 지시 방식, 지시의 순서·주제 | 글과 흐름에 남음 | 쓸 수 있음 |
| 보낸 시각·보낸 간격 | 메시지마다 시각이 붙어 옴 | 쓸 수 있음 |

기준 자료는 이미 있습니다. 창 「페이블 261104」의 대표님 말씀 원문과 모델통제 이력의 말씀 요지 760줄입니다.

## 3. 제안하는 체계 — 세 겹

**첫째 겹 · 기기 잠금(가장 확실한 막이).** 사람이 노트북 앞에 앉는 것은 운영체제가 막아야 합니다. Windows 화면 잠금을 무입력 1~2분으로 줄이고, 휴대전화가 멀어지면 잠기는 「동적 잠금」을 켭니다. 이 겹이 뚫리지 않으면 아래 두 겹은 쓸 일이 없습니다.

**둘째 겹 · 위험한 지시 앞에서의 재확인.** 패턴이 정상으로 보여도, 아래 지시는 id.html 재확인 기록이 있어야만 수행합니다.

| 재확인이 걸리는 때 | 까닭 |
|---|---|
| 무입력 뒤 첫 지시(기준 시간은 대표님이 정하심, 제안 15분) | 자리를 비운 시간과 겹침 |
| 결재(허가·승인·파기), 정책·규칙의 파기·변경 | 되돌리기 어려움 |
| 삭제·휴지통 이동, 밖으로 나가는 발송(메일·게시), 배포 | 밖에 흔적이 남음 |
| 비밀번호·계정·접근 권한에 닿는 지시, 「재확인을 끄라」는 지시 | 사칭자가 가장 먼저 노릴 곳 |

**셋째 겹 · 말씀·타이핑 패턴 대조(보조 신호).** 모델이 지시를 받을 때마다 기준과 견주어, 여러 항목이 한꺼번에 어긋나면 수행을 멈추고 재확인을 띄웁니다. 견주는 항목: 높임·반말, 문장 길이, 되묻는 말버릇, 자주 쓰는 낱말과 사업 용어의 쓰임, 구두점 버릇, 음성·타이핑의 갈래, 평소 하지 않던 종류의 지시(자료를 밖으로 보내라, 규칙을 꺼라 등).

어긋남이 잡히면: ① 그 지시는 수행하지 않고 보류 ② SC-00 에 「신분 재확인 대기」 알림 ③ 이력에 시각·까닭 기록 ④ 재확인이 통과되면 보류한 지시를 이어서 수행, 통과되지 않으면 그 사이 지시 전부를 무효로 표시.

## 4. 위험성

| 위험 | 내용 | 줄이는 방법 |
|---|---|---|
| 흉내 | 반말·말버릇은 옆에서 본 사람이 따라 할 수 있음. 패턴 대조는 신분 증명이 되지 못함 | 셋째 겹은 보조로만 쓰고, 막는 일은 첫째·둘째 겹이 맡음 |
| 헛경보 | 피곤·흥분·음성과 타이핑의 전환으로 대표님 본인 글이 어긋나 보임 | 한 항목이 아니라 여러 항목이 겹칠 때만 멈춤. 헛경보는 이력에 남겨 기준을 고침 |
| 놓침 | 모델의 판단은 확률이라 짧은 지시 한 줄은 구별되지 않음 | 짧아도 위험한 지시는 둘째 겹이 무조건 재확인 |
| 기준 자료 유출 | 말버릇 기준은 그대로 「흉내 교본」이 됨 | 기준은 비공개 저장소와 ic.hiven.ai.kr(접근 통제) 안에만 두고, 화면에는 수치만 표시 |
| 재확인 무력화 | 사칭자가 「재확인하지 마」라고 지시 | 재확인을 끄거나 느슨하게 하는 지시는 id.html 통과 뒤에만 받음 |
| 번거로움 | 재확인이 잦으면 일이 끊김 | 기준 시간과 대상 지시를 대표님이 정하시고, 통과 한 번이 그 묶음 전체에 유효 |

## 5. 필요한 것

1. 대표님이 정하실 값: 무입력 기준 시간, 둘째 겹의 대상 지시 목록, 어긋남 알림을 받을 곳(메일 주소).
2. 지금 규칙의 손질: 「신분 확인은 인스턴스가 바뀌기 전까지 한 번」 규칙에 「위 두 경우는 다시 한다」를 덧붙임.
3. 만들 것: 말씀 기준표(원문에서 수치로 뽑음), 보류·무효 표시를 SC-00·SC-17 에 올리는 화면, id.html 재확인 기록과 지시 보류의 연동.
4. 대표님 PC: 화면 잠금 시간 단축과 동적 잠금 켜기.

## 6. 권하는 순서

첫째 겹과 둘째 겹을 먼저 시행하고, 셋째 겹은 기준표가 쌓이는 대로 보조로 붙이는 것이 안전합니다. 패턴 대조만으로 신분을 가리는 방식은 흉내와 헛경보 때문에 권하지 않습니다.
