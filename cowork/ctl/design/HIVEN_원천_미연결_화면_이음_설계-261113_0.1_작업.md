# HIVEN 원천 미연결 화면 이음 설계

- 판: 0.1 작업본 · 만든 때 2026-11-13 · 만든 모델 Opus 5.5 · 검수 Fable
- 근거: Fable 지시(대표님 2026-11-13 18:07~18:26 지시 묶음) · `cowork/ctl/aics_scmap.tsv` 「원천에 안 이어짐」 5개 화면과 「손으로 쓰는 원천」 37줄 · 화면 코드 실측(Playwright, 바깥 호출 막음)
- 이번 판에서 화면 코드(views*.js · data.js · sec*.js · index.html)는 고치지 않았습니다. 아래는 설계이며 개발 지시는 Fable이 따로 냅니다.
- 원칙: 지어낸 값·시험값·시뮬레이션 값을 원천으로 쓰지 않습니다. 원천이 없으면 화면은 「확인 안 됨」과 마지막으로 확인한 때를 함께 보입니다. Cloudflare(ic.hiven.ai.kr) 호출을 늘리지 않습니다. 서버에만 있는 기록은 모델이 정해진 차례에 한 번 내려받아 저장소 사본으로 두고, 화면은 저장소 사본만 읽습니다.

## 1. 먼저 바로잡을 판정 — 「원천에 안 이어짐」 다섯 화면의 실제

`aics_scmap.tsv`는 시험 페이지(`test/index.html`)에서 화면을 연 뒤의 요청만 받아 적었습니다(`tools/sc_fetch_measure.js` 9~10줄). 그래서 ① 시험 페이지가 읽지 않는 `sec.js`·`sec2.js`의 값, ② 페이지를 열 때 한 번 또는 주기로 미리 읽어 둔 값, ③ 코드에 박힌 값을 구분하지 못했습니다. 본판(`index.html`)을 열어 다시 잰 결과는 다음과 같습니다.

| 화면 | scmap 판정 | 지금 값이 실제로 오는 곳 | 코드 근거 | 바로잡은 판정 |
|---|---|---|---|---|
| SC-03 | 원천에 안 이어짐 | ① 체계 표 전체 = 코드 안 배열 `hvEM` ② 매뉴얼 7종 = `cowork/ctl/manuals.json`을 `tools/gen_views8.py`가 `views8.js`에 구워 넣은 값 `hvMAN` ③ 지금 발령 단계 = 이 브라우저 `localStorage` 「hvsec」의 열쇠 오류 수 | views7.js 3~181줄 · views8.js 2줄 · views8.js 31~34줄 `live()` · sec2.js 4~5줄 `st()` | 일부 이어짐(매뉴얼은 원천 파일 있음, 단계는 한 기기 기록, 체계 표는 코드 값) |
| SC-04 | 원천에 안 이어짐 | ① 통합 경보 = ic.hiven.ai.kr `/__sec/list?n=1000`(Cloudflare 작업자 저장소 SecLog) ② 단말 경보 = 이 브라우저 `localStorage` 「hvsec」 ③ 신뢰 기기 = ic `/__dev/list` | sec.js 57~58줄 · sec.js 8줄 · sec.js 77줄 | 이어짐(원천이 저장소 밖 서버에 있음). 시험 페이지는 sec.js를 읽지 않아 잴 수 없었음 |
| SC-06 | 원천에 안 이어짐 | 코드에 적어 둔 `HVR` 값(노트북 HiClo 판정 파일을 2026-11-04 15:56에 사람이 보고 옮긴 값) | views0.js 4~16줄 · 110~115줄 | 안 이어짐(맞음). 값은 실측을 옮겨 적은 옛 값 |
| SC-07 | 원천에 안 이어짐 | ① 경보 원장 = `cowork/ctl/alerts.tsv`(106줄, `tools/gen_alerts.py`) ② 아래 표 = `HVR.issues` 옛 값 4줄 | views0.js 140~144줄 `hvAlertLedger` · views0.js 173줄 `hvMetaLoad`(30초마다, 200줄) · views0.js 137줄 | 일부 이어짐. 페이지가 열릴 때부터 30초마다 미리 읽어 두므로 화면 전환 때 요청이 잡히지 않았음 |

같은 까닭으로 scmap의 SC-00·SC-01·SC-17 줄(같은 16개 파일)은 「그 화면이 읽는 원천」이 아니라 「페이지 전체가 1초마다 읽는 원천」입니다(views9.js 10줄 `load()`, 227줄 `setInterval(load,1000)`). 화면별 원천 연결표를 다시 만들 때는 화면 함수가 실제로 쓰는 변수(P.H, P.AL, P.CS17 …)로 갈라 적어야 합니다.

## 2. 이음 공통 규칙

1. 원천 파일은 `cowork/ctl/` 아래 TSV 한 장, 첫 줄 머리글, 시각은 한국 시각 `yyyy-mm-dd HH:MM`.
2. 모든 원천 파일 맨 끝 칸 또는 머리 다음에 「만든 도구」와 「잰 때」를 남깁니다. 화면은 잰 때가 기준 시간을 넘으면 값 옆에 「정지 N시간」을 붙입니다(views0.js 19줄 `hvStop`과 같은 표기).
3. 값이 없으면 칸을 비우지 않고 `확인 안 됨`을 적습니다. 0건은 실측 0건일 때만 `0`입니다(views0.js 139줄 주석의 「원천 연결 전」 규칙과 같음).
4. 서버(Cloudflare) 기록은 화면이 직접 부르지 않습니다. 모델이 정해진 차례(작업 차례 시작 때 한 번)에 내려받아 저장소 사본을 만들고 커밋합니다. 예약·훅은 쓰지 않습니다.
5. 실측 원본(내려받은 서버 기록 사본)은 이름·내용을 바꾸지 않습니다(DR-14). 가공본은 따로 만듭니다.

## 3. SC-03 이상징후 및 보안체계 시스템

## 4. SC-04 침입 예측·예방·대응·조치 시스템

**지금**: 통합 경보 표는 화면을 열 때마다 ic `/__sec/list?n=1000`을 부름(sec.js 58줄). 신뢰 기기 표도 열 때마다 `/__dev/list`(sec.js 77줄). 단말 경보는 이 브라우저 저장소.

**이을 원천**: 3절의 `sec_log.tsv`(공개 저장소 사본은 IP 칸 없음). 신뢰 기기는 `cowork/ctl/trusted_devices.tsv`(칸: 기기 이름 · 상태 · 기기 표지 앞 6자리 · 처음 등록 · 최근 변경 — IP·국가는 비공개 저장소에만).

**화면 표시 규칙**: 통합관제(ic) 본판은 지금처럼 서버를 직접 읽어도 되며(로그인 상태), 공개 주소 본판(hiven.ai.kr)은 저장소 사본만 읽고 「사본 HH:MM 기준」을 붙임. 사본이 없으면 「확인 안 됨」.

**난이도**: 중. 호출 효과: 공개 주소에서 SC-04를 열 때마다 생기던 ic 호출 3건(me · list · dev/list)이 0건이 됨.
