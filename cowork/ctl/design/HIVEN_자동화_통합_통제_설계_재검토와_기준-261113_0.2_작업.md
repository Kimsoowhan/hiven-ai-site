# HIVEN 자동화 통합 통제 설계 재검토와 기준 0.2 (작업본)

작성: Fable 5.2 · 2026-11-13 · 근거: 대표님 19:13·19:16·19:17·19:22 지시(모델통제 이력 1312~1316) · 앞 판: 0.1(같은 폴더)

## 1. 이 판에서 한 일

대표님이 짜신 구조(SC-00~SC-21)를 기준으로 그대로 두고, 바깥 사례(Anthropic · Google · 국내 공공 인증)를 대어 더 필요한 것을 찾았다. 폴더의 바탕이 되는 세 분류 체계(문서 · 데이터 · 바깥 조직 협업)가 HiBiz 안에 자리가 있는지, B2C → B2B → B2G로 넓힐 때 버티는지 보았다.

## 6. 사업 간 연계 (다시 맞춘 것)

- 기준의 흐름: HiDAM(제정) → HIVEN 내부 적용(06_01) → HiBiz 운영 규칙(07_01) → SC-15 검사 → 폴더마다 00 색인.
- 제품의 흐름: HiDAM(기준) → HiCoffer(첫 제품, PC 베타1) → HiSilver. 배포는 SC-09, 베타 고객 값은 SC-20, 문의는 SC-01·SC-14.
- 바깥의 흐름: SC-19(앞선 준비) → SC-21(계약, 열 갈래) → SC-18(맞닿아 돌아감). PG사는 주 자리 SC-18.
- 고객의 흐름: SC-20(약관·회원·베타·개인정보) → SC-01 고객 지원의 원천·기준.
- 확인의 흐름: 모든 화면 → SC-02 종합 현황 → SC-00 결재. 문서는 SC-15.
- 화면 22개 ↔ 1층 폴더 35개 ↔ 원천 대장: 같은 폴더의 「화면 폴더 대장 정합표」에 줄마다 적음.

## 7. 확장을 염두에 둔 폴더 기준

1. 1층 폴더 번호 띠는 그대로 둔다: 00~09 그룹·바탕, 10 정부, 11~17 사업군, 20 마케팅, 31~39 기술, 40~44 고객·바깥, 80 참고, 91~95 Claude.
2. 기업·공공으로 넓힐 때 1층 폴더를 새로 만들지 않고 40~44 안에 갈래를 둔다: 약관(44)은 시장 칸, 계약(43)은 열 갈래 아래 상대별, 협력사(42)는 공공 조달·인증 줄.
3. 고객 조직별 자료가 생기면 40_고객지원 아래가 아니라 43 계약 갈래 아래 계약 번호 폴더에 둔다(계약이 기준).
4. 폴더·파일 이름에 보호 등급을 넣지 않는다(데이터 분류 체계 0.1의 원칙 유지). 등급은 대장에만.
