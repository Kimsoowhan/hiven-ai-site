## 1. 목적과 범위

### 1-1. 목적

HIVEN 분류 체계는 HIVEN과 대표님의 모든 문서·폴더·파일·데이터를 하나의 코드 체계로 분류하는 기준 전체입니다. 이 문서는 하위 분류 체계 5개의 구성·위계·연결·검증을 한곳에 묶고, 이 체계가 Hi DAM 제정 표준의 HIVEN 적용 사례 #1(B2B)이며 대표님 개인(KS)이 B2C 적용 사례 #1임을 밝힙니다.

### 1-2. 적용 범위

HiBiz 작업 공간 전체(1단 폴더 00~90)와 그 밖의 대표님 데이터(바탕 화면·다운로드·사진·동영상·음악·OneDrive·G 드라이브)입니다. 운영체제·프로그램 영역(AppData 등)은 대상이 아닙니다. 옛 Mbiz 공간(10/30 기준 4,421파일 적용 실적)은 옮길 때 NM-1로 바꿉니다.

## 2. 구성 — 하위 분류 체계 6개(0.3에서 협업 분류를 더함)

### 2-1. 구성표

| 순서 | 하위 체계 | 답하는 질문 | 정의 문서 | 상태 |
|---|---|---|---|---|
| 1 | 코드 분류 체계 | 무엇으로 부르나 | HIVEN 코드 분류 체계(CCS) **0.2** | 개정 작업본 — 조직 코드 7사업군 반영 |
| 2 | 문서 분류 체계 | 무슨 문서인가 | HIVEN 문서 분류·명명 지침(DOC) 1.2 | 유지 — 계열 코드 등록부는 CCS 0.2 3-7 반영 필요(후속) |
| 3 | 폴더 분류 체계 | 어디에 두나 | HIVEN 폴더 분류 체계(FDS) **0.2** | **독립 발행**(0.1은 파일 없음) |
| 4 | 파일 분류 체계 | 이름은 무엇인가 | HIVEN 파일 분류·코드 체계(FCS) **0.4** | 개정 작업본 — 이름 NM-1 |

| 6 | 협업 분류 체계 | 바깥의 누구와 어떤 관계인가 | HIVEN 협업 분류 체계 0.1(작업본, 계열 코드 등록 전) | **신설(0.3)** — Stakeholder · 이해관계자 및 협력사 · 계약 상대(열 갈래) · 고객(개인·기업·공공). 폴더 41~44와 화면 SC-18~21의 기준 |

※ HiBiz 세대 정책군 HiBiz 분류 정책군(GBP-2) 0.2(03_기준_명명분류)는 위 5체계의 HiBiz 적용 정책이며, 5체계가 정식 발행되면 GBP-2의 「1.0 확정 때 정함」 항목(조직 코드·계열 코드·폴더 약어 등)은 이 5체계 값으로 닫습니다.

### 2-2. 위계와 흐름

코드 분류가 모든 체계의 바탕입니다. 순서: 코드 → 문서 → 폴더 → 파일 → 데이터. 앞 체계의 값을 뒤 체계가 그대로 가져다 씁니다(파일 대장의 조직·종류 = 문서 분류 값, 폴더 약어 = CCS 폴더 약어 코드 종류).

### 2-3. 두 세대의 일원화 [정립안 0장]

10/30 Mbiz 세대(CCS 0.1·FCS 0.3·DTS 0.1)와 11/01 HiBiz 세대(GBP-2 NM-1)가 공존했습니다. 이 개정으로 **하나의 발행 체계(Hi DAM 제정·단일 배포)**가 되며 GBP-2는 그 「B2B 적용 사례 #1」입니다. 체계 자체의 결함은 없고 세대 전환(Mbiz→HiBiz)과 7사업군 전환이 코드·문서에 반영되지 않은 것이 부정합의 원인이었습니다.

## 5. 통합 규칙 — 문서·데이터·파일·폴더·코드 한 장 [정립안 5장 9항]

| 번호 | 규칙 |
|---|---|
| 1 | **제정·발행**: 모든 분류 기준은 Hi DAM이 제정·단일 발행·단일 배포. HIVEN 내부(HiBiz)는 B2B 적용 사례 #1, 대표님 개인(KS)은 B2C 적용 사례 #1 |
| 2 | **코드**: 규모 › 조직(7사업군+HQ·HF·KS) › 종류 › 형태 › 상태. 한 코드 한 뜻, 폐지 재사용 금지, 등록부 먼저 |
| 3 | **문서**: 종류 코드 13 + 계열 코드(byline에만). 제목 = 파일명. 버전 0.1 시작, 작업본 「_작업」, 최종화는 Fable |

| 5 | **파일**: 이름-YYMMDD_x.x(NM-1), 공백·특수문자 0, 코드·등급은 대장에만 |
